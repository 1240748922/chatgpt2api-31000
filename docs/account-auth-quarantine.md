# 3.2.29：过期凭据过滤与鉴权核验隔离

## 问题与证据

基于 `2bbcbf2` 排查：一条失败请求切换了四个不同账号，四次均在
`/backend-api/files` 上传登记阶段收到 `401 / token_expired`，尚未提交生图。
生产账号、凭据、提示词和原始日志未写入仓库。

合成账号与临时 SQLite 复现了两条路径：

1. 过期 AT 因为存在 RT 被视为可恢复；刷新失败后进入五分钟退避，
   后续 `ensure_access_token` 直接返回过期 AT。第一次刷新失败会换号，
   下一次请求反而将过期 AT 交给上传接口。
2. 上游鉴权拒绝后账号进入 `pending`。后台核验遇到超时或网络错误时，
   状态被改为 `error` 并清除核验标记，尚未恢复的凭据重新进入候选池。

这些是本地可复现的调度缺陷；单条业务日志不包含账号刷新历史，尚不足以
判断生产环境每一次 401 都来自同一条路径。未知撤销、首次远程拒绝和已经在途
的请求仍可能产生 401。

## 修复

- 过期且处于刷新退避的账号在本地筛选时跳过，不消耗上游生图换号次数。
- Token 维护的跳过、失败回退和成功返回分支均检查 AT 可用性；
  没有 RT、退避中或后台忙碌时也不再返回已知过期 AT。
- 未过期的 AT 在 RT 刷新暂时失败时仍可使用。恢复失败属于临时不可调度，
  不因此删除账号或标记 RT 永久失效。RT 轮换继续使用现有 single-flight/CAS。
- Token 维护完成后仅在内存中重新检查当前账号行，防止维护期间已被隔离的
  账号进入业务请求；不增加全池扫描、数据库查询或逐请求上游预检。
- 核验失败保留 `pending`、核验 ID、作用域和删除策略，同时保存错误原因。
  共享数据库快照和重启不再清除带核验 ID 的隔离状态。
- 核验网络失败至少退避 30 秒；RT 刷新失败沿用五分钟退避。强制排队请求也
  不绕过该退避，worker 收尾不立即重跑。到期候选在应用 `limit` 之前筛选，
  避免列表开头的冷却账号挡住后面的可核验账号。
- 已有生命周期 watcher 在允许后台维护时恢复到期核验；保留原低负载门控。
  高负载下隔离可能持续更久，期间业务使用其余可用账号。管理员主动刷新仍可
  使用原有操作。核验成功后恢复调度；终结性失效沿用原异常/自动移除策略。
- 普通健康账号的额度查询网络错误仍记录为 `error`，不因此进入鉴权隔离。

## 回归

新增鉴权回归覆盖：刷新退避、有效 AT、过期无 RT、远程提前失效、正常轮换、
single-flight、文本换号、并发核验、跨实例快照、重启隔离、到期恢复、
核验成功、旧凭据核验结果丢弃、worker 防止紧密重试，以及终结性失效处理。
四个过期候选加一个健康候选的协议测试只进入健康账号，并仅记录一次生图尝试。

测试只使用合成凭据、临时数据库、mock 上游或 loopback，不调用真实上游账号。
全量测试中的注册配置应使用示例配置注入，勿使用生产配置。浏览器测试需另行
安装 Playwright/Chromium；Node 回归无需这些依赖。

2026-09-23 本地结果：新增鉴权回归 29 项通过；Python 全量 321 项通过，
2 个浏览器测试模块因未安装 Playwright 跳过；3 组 Node 回归、Python 语法检查
和 `git diff --check` 通过。保留一条 TestClient/httpx 弃用警告。

## 发布与验证

应用版本标记为 `3.2.29`。本地修改不等于镜像已经发布：提交并推送后，等待
Actions 成功，再将服务器镜像固定到该提交实际产生的 `sha-xxxxxxx` 标签。
仓库默认 Compose 仍锁定旧镜像，单独拉取源码不会更新运行中的应用。

无数据库结构迁移，不修改密钥、账号数据、代理、生图/超分并发、普通换号预算
或部署拓扑。上线时按现有多实例部署流程备份并低峰重建应用容器，注意在途请求。
核对 `/version` 与各实例实际镜像，观察上传登记阶段的 `auth_invalid` 次数、
后台刷新错误、待核验账号数量以及健康账号成功率。此修复不承诺消除上游故障。
