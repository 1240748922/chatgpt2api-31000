# 导入 v2：实现与本地测量

版本：3.2.4。对比基线：`1545f29`（已包含独立 importer 的上一版）。

## 测量方法

Windows、Python 3.13、临时 SQLite 数据库；每次 7,000 条合成 AT，token 长约 1,500 字符，每批 250 条。测量提交到所有账号提交成功的总时间，关闭额度同步，不访问 OAuth、生图或其他上游。两版在同一机器顺序执行；账号数量与实际入库结果均校验。现有账号初始化不计入补号耗时。

| 场景 | 上一版 | 导入 v2 | 吞吐提升 |
| --- | ---: | ---: | ---: |
| 空池导入 7,000 条 | 13.7407 秒 | 4.4789 秒 | 约 3.07 倍 |
| 已有 7,000 条，再导入 7,000 条 | 15.2323 秒 | 4.0714 秒 | 约 3.74 倍 |

这是单次本地样本，不是生产压测承诺。空池新版样本曾与功能测试并行，第二组顺序执行。服务器使用 PostgreSQL，实际磁盘、CPU、数据库竞争、文件大小与网络都会改变结果。RT 兑换及额度同步必须另外计时，不能用本地 AT 入库速度代表这些网络阶段。

复现（默认创建临时数据库，绝不使用部署数据库）：

```bash
python tools/benchmark_account_ingest.py --output ingest-empty.json
python tools/benchmark_account_ingest.py --existing 7000 --output ingest-populated.json
# 对另一份源码执行同一脚本，可添加 --code-root /path/to/baseline
```

## 性能改变

- 数据库新增账号改为 executemany 批量插入，保留同一事务内的 CAS 和任务进度提交。
- 大文件提交时分块，工作线程每次只加载当前块，避免每批解析全部凭证。
- 复用已经归一化的账号指纹，减少反复哈希整个号池；导入结果 ID 去重采用集合。
- RT 并发兑换使用独立限流器与工作线程，避免 RT 网络请求占满 AT 本地保存用的槽位。兑换结果及时持久化，再分批入账号池。
- 额度同步的在途窗口随已有并发配置调整，不再固定每轮最多 10 条。

独立进程隔离了 Python 请求线程和维护槽位，仍与生图实例共用数据库及主机资源。提高并发不能无限提高上游或数据库吞吐。

## 正确性检查

覆盖管理员权限、登录复用、多文件/JSON 解析、坏 JSON 拒绝、RT 并行与部分失败、凭证脱敏、兑换后入库中断恢复、事务回滚、重复账号状态保护、不同批次配置恢复、旧任务兼容、额度阶段使用兑换后的 AT，以及导入/数据库阻塞期间健康账号读写与生图完成状态合并。没有使用真实账号发起生图或兑换。
