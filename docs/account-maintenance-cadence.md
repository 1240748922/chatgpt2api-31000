# 有积压时连续维护，避免固定空等（3.2.38）

## 原因与变化

旧版本不是“每 30 秒只能处理 2 个”：一轮内可以连续运行多个小批，每类调用保留 20 秒时间片。但整轮结束后无条件等待 `CHATGPT2API_MAINTENANCE_RETRY_SECONDS`（默认 30 秒），大池仍有积压时也会空等。

3.2.38 将健康积压的继续执行与空闲/压力重试分开：

| 状态 | 下一轮等待 |
| --- | --- |
| 性能策略为 normal、本轮推进了队列、仍有待处理项 | 默认 2 秒 |
| 刚处理完候选窗口 | 等到下一次候选筛选时间，执行耗时不再额外叠加完整 30 秒 |
| 减速/试探/暂停、无任务、没有进展、本轮异常、旧版 idle 策略 | 原 retry 间隔，默认 30 秒 |

每个小批开始前仍检查性能，整轮完成后再检查一次。每类调用仍保留 20 秒时间片（不会中途强行打断正在请求的批次），轮流推进 AT 续期、未知额度、限流复查。仍使用同一个维护实例/线程，不新增并行维护者。

“本轮异常”指维护调用抛出异常；单个 RT 被确认失效会按原规则标记，不反复重试该凭据，其他账号仍可继续。上游限流/服务错误仍参与原性能压力判断。

## 避免加速带来的副作用

- AT/限流待办继续使用原队列；未知额度候选也保留未完成窗口，不在每个短循环中重选整个池。
- 全池未知额度筛选、后台鉴权核验的扫描频率不快于原 retry 间隔；AT/限流全量发现仍沿用原生命周期配置。没有开启 2 秒一次的全池扫描。
- 继续处理未知额度窗口前，只按至多 50 个队列 token 查当前缓存；不强制完整快照加载，过滤已检查、刚失败、忙碌、已禁用、待核验或删除的账号，并跟随本地 AT 轮换别名去重。
- 不清凭据租约、不重放结果不确定的 RT 请求，不取消既有 RT/额度失败退避，不放行过期 AT。
- 此版**不提高每批并发上限**，默认仍为 2；先移除不必要等待，便于单独验证影响。注册、备份、保留清理仍使用原等待策略。
- 不修改生图/超分并发、导号加速、预热、代理、自动删除开关、前端样式或数据库结构。等待使用 `Event.wait`，停机可立即唤醒，不要求等完整 30 秒。

## 配置与回退

新增可选环境变量，Compose 默认提供，不需要为了默认行为修改服务器 `.env`：

```dotenv
CHATGPT2API_MAINTENANCE_CONTINUE_SECONDS=2
```

该值有下限 1 秒，实际不大于原 retry 间隔。要保留以前的整轮等待，可设为 `30`（原 retry 也是 30 时）；该配置在下次安全重建应用后生效。不要把通用 retry 改成 2，否则会同时提高空闲/压力下的重试频率。

应用回退镜像为 `sha-9760705`（3.2.37），无需数据库回滚。升级/回退先暂停新请求并排空在途任务，不能把重建运行中的生图容器当成无中断更新。

## 确定性验证

模拟 70 个待续期账号，每批 2 个，每批请求耗时 3 秒：第一轮处理 7 批，在第 21 秒结束时间片。相同输入下，旧版下一轮在第 51 秒开始，新版第 23 秒开始，账号处理顺序不变、没有重复。这只是对固定空等的对照验证，不是生产整体吞吐或恢复成功率保证。

根目录 PowerShell：

```powershell
$env:PYTHONPATH="$PWD\src_extract;$PWD\GPT-Register-Tool-main"
python -X utf8 -m pytest src_extract/tests/test_account_maintenance_cadence.py -q
```

测试还覆盖未知额度队列续跑不重扫、执行前重校验、凭据轮换、压力骤升立即恢复长等待、旧策略/回退、空池和异常不忙循环、真实 Event 停机唤醒。失败对照记录保存在本地 `.runtime/maintenance-cadence-before.txt`，完整发布回归记录在 `.runtime/release-3.2.38-tests.txt`。

## 更新后观察

看“账号可用性 → 同步进度”：有剩余队列且性能正常时，累计处理次数应更连续，“下次检查”通常较近；页面约 3 秒采样，所以瞬时正在处理 0 不等于没有维护。队列为空、候选发现周期未到或调度降速时仍会等待。

如果仍是“成功 0、失败持续增加”，应检查续期错误，不能把失效 RT 当成等待问题；此补丁无法恢复已经失效的凭据。数据库/写锁 P95 升高时仍会减速或暂停。本版没有修改网关；此前概览 404 的永久配置是否安装，仍需用 `nginx -T` 核对 `dynamic-backends-v1`。
