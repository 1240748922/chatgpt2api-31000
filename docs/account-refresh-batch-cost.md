# 3.2.44：减少大账号池续期批次的内存复制

## 现网证据与结论

2026-10-02 的只读日志检查确认近期文生图 502/504 比例上升。最近可复核窗口
（北京时间 10/1 11:14:39–10/2 10:39:56）文生图为 250/3443（7.26%），
图生图为 2/6950（0.0288%）。这些是最终 502/504 比例，不是完整失败率；
分母包括文字回复等状态。不同日期的内容、接口构成、并发、账号批次未匹配，
不能据此认定 8000、9000 或 10000 个账号是故障阈值。

失败尝试的取号 P95 约 150ms 或以下；长耗时主要在无图片后的轮询、网络等待
和跨账号重试。没有同版本同负载的 5000 账号历史窗口，不能确认或排除池规模
的间接影响，也不能把本次维护优化当成上游超时的完整修复。

另确认 `_exchange_access_tokens` 在每个续期小批次结束时调用 `list_accounts`：
即使只处理两个账号，也在账号锁内复制整个池的记录并补充 `image_inflight`，
随后只是用管理 ID 判断本批账号是否仍然存在。这是可消除的线性复制开销。

## 修改与边界

批次收尾改用 `_existing_account_ids`，只读取管理 ID，结果集合只保留本批目标，
找到全部目标即停止扫描；保留原快照刷新与锁保护。最坏情况下仍扫描全池的 ID，
不声称已将所有账号池操作变成常数时间。批次目标在末尾或已删除时尤其如此。

RT 轮换后仍通过稳定管理 ID 匹配；刷新期间删除的账号继续进入 `removed_ids`，
不会被误报为仍可更新。后台自动续期与管理员强制刷新均使用该路径。

此改动不修改上游轮询时限、普通重试次数、严格凭据准入、后台维护并发、
导号、上传、超分、存储或账号清理规则；没有数据库迁移，不读取或修改真实 `.env`。
已完成 code 消息不等于图片生成终止，现有证据不足以安全缩短这类任务的等待。
