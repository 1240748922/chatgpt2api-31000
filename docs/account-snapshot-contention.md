## 已复现的持续阻塞

生图完成仍会更新账号的成功次数、额度等字段。其他实例发现账号集合 revision 改变后，即使只改变一行，也会读取并刷新完整账号快照。普通刷新 TTL 为 5 秒；这是请求触发的过期检查，并非每个请求都同步重新读库。

数据库读取和账号归一化原本已在后台执行，但安装新快照时仍在取号共用的锁内对整个持久化基线执行 `deepcopy`。所以“导入结束”不会消除这个与号池规模有关的重复成本。

新增的隔离并发回归暂停这次复制，再尝试取号：旧代码中取号被同一把锁阻塞，测试以 `TimeoutError` 失败；修复后复制未结束时即可取号和释放槽位。复制期间发生的额度扣减与成功计数变更仍会在新快照安装时合并，导入的新账号可见，实时状态与持久化基线继续保持独立。

修复将新快照的独立基线复制移到获取调度锁之前。重新拿锁后仍检查 revision、合并并发的本地状态、处理凭据轮换及通知等待者。没有改成跳过校验或直接覆盖实时状态。

## 本地测量

使用 7000 和 29429 个合成账号，每条归一化后 35 个字段、合成 AT 约 1500 字符，无可用真实凭据。只测快照归一化、安装和本地取号；单个实例、无上游请求、无生产数据库 I/O。每种规模连续改变单个账号三次，均观察到三次完整快照读取。

| 账号数 | 修复前每轮最长调度锁持有时间 | 修复后每轮最长调度锁持有时间 |
| --- | --- | --- |
| 7000 | 241 / 257 / 344 ms | 11 / 15 / 13 ms |
| 29429 | 749 / 758 / 717 ms | 56 / 68 / 69 ms |

这些是本机分开运行的样本，不能换算为生产整体请求加速比例。完整快照仍有 O(N) 的处理、分配与归一化成本，也仍有锁内的状态合并。没有复现线上全部 16.4 秒，没有证明此次优化能解决上传的 17.7 秒或所有上游超时。

复现（可用 `--code-root` 指向旧版本源码）：

```bash
python tools/benchmark_account_snapshot.py --counts 7000 29429 --output snapshot-results.json
```

工具仅使用合成账号，强制将导入的服务单例指向临时 SQLite，测量路径使用内存快照；不连接部署数据库或上游。

## 取号诊断与界面名称

新增原始请求日志字段，成功和失败均记录，跨凭据维护失败后的内部重选累加：

| 字段 | 含义 |
| --- | --- |
| `account_snapshot_check_ms` | 进入取号时的快照检查及后台刷新调度耗时，包含该调用内的锁等待；不等于后台刷新执行耗时 |
| `account_candidate_total_ms` | 所有内部候选获取调用的总耗时，包含其筛选及等待 |
| `account_token_maintenance_ms` | 所有候选的 AT 维护总耗时，可能包含锁、等待其他刷新、RT 兑换和保存；不能直接等同于 OAuth 网络耗时 |
| `account_candidate_attempts` | 候选获取的调用次数，包含最后一次失败调用；不是已提交的生图次数 |

前三项是 `account_wait_ms` 内部阶段，不能再次加到整条请求总耗时中。失败候选的槽位释放及调用间的小段开销不在三个阶段内；现有 `selection_wait_ms` 保持只描述最后一次候选获取的含义。

按用户要求，左上角名称改为“Chatgpt生图系统”，GitHub 图标链接指向 `https://github.com/1240748922/chatgpt2api-31000`。其他前端模块只同步缓存标记，避免旧页面缓存或混用 Vue 运行时。

没有调整账号并发上限、选号顺序、额度规则、RT 刷新条件、重试次数、上游请求、导入任务、数据库格式、Compose、Nginx 或服务器配置。
