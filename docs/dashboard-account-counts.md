# 概览账号分类统计（3.2.42）

## 问题与修复

3.2.41 现网只读采样中，概览异常账号为 0，而账号管理的异常筛选返回 179 个账号。两次接口调用不是冻结快照，但源码和本地合成回归均确认统计口径有差异：概览只计算持久化 `status=异常`，管理列表还会计算“AT 已失效且没有可用 RT”的账号。

3.2.42 中，`AccountService.get_stats()` 复用账号管理的 `account_status_category()`，每个账号仅归入正常、限流、异常、禁用中的一个类别；正常账号额度汇总也以该分类为准，不再纳入凭据不可恢复的异常账号。原本这些账号就不能按正常凭据生图，数字变化不会消耗或删除额度。

| 情况 | 管理及概览分类 |
| --- | --- |
| 已禁用 | 禁用优先 |
| 持久化状态为异常 | 异常 |
| AT 过期/明确失效，RT 缺失或已明确失效 | 异常 |
| AT 过期，但存在未明确失效的 RT | 保留原正常或限流状态，可后台恢复 |
| 历史 RT 失败但尚未复核 | 不因历史错误新增异常，原待复核分类保留 |
| AT 仍有效，RT 已失效 | 不因 RT 单独失效新增异常 |
| 仅上传冷却、普通超时、AT 有效期未知 | 不因这些条件新增异常，原调度规则保留 |

这修复的是管理类别，不替代“账号可用性”中的严格凭据准入、就绪额度、上传冷却或并发槽位判断。后台删除仍使用原配置和原判据；读取概览不会写入异常状态，也不会触发删除、续期或额度同步。

## 性能与验证

- 使用已有账号快照；分类放在账号锁外，整次统计固定一个时间点。
- JWT 时间解析复用现有 LRU 缓存；计数/筛选不再构造完整行展示信息或清洗历史错误文本。
- 本机 20,000 个合成账号统计：首次约 254ms，缓存命中后 7 次中位数约 138ms；不含数据库快照加载或上游调用，不能视为生产耗时保证。
- 新增回归覆盖 AT 到期边界、凭据恢复、RT 单独失效、历史待复核、禁用优先、分类互斥、额度、健康值，以及真实 `/api/dashboard` 响应与账号管理筛选一致。
- 不改前端资源、数据库表、后台维护阈值、生图/导入/超分配置。现网数据持续变化，独立接口采样可能短暂有差异。

## 更新后验收

1. 确认 `/version` 为 `3.2.42`，镜像标签与 [发布说明](../VERSIONING.md) 一致。
2. 打开概览和账号管理的“异常”筛选，观察两处计数在账号池稳定时一致；上传受限不是鉴权异常。
3. 检查正常、限流、异常、禁用相加等于账号总数。上传受限是可重叠能力状态，不参与该求和。
4. 凭据恢复后，异常计数应随下一次快照/概览刷新减少；不需要重写旧账号状态。

可本地执行 `python -m pytest tests/test_account_stats.py tests/test_account_cleanup_actions.py tests/test_dashboard_operations.py -q`（目录 `src_extract`），只使用合成账号。应用可回退至 3.2.41，无需回滚数据；旧版会重新出现统计漏项。
