# 3.2.21：概览集群并发与导入历史显示上限

## 根因与修复

Nginx 将管理 API 发给 app0，生图却分发到 app0–app7。旧版 `build_dashboard_view()` 直接读取当前进程的 `operations_snapshot()`，所以“当前并发”只显示 app0，不是全局总数。隔离回放 8 个进程计数 `[1, 125, 20, 0, 3, 40, 8, 2]`，旧代码返回 1，修复后返回 199。

- 每个实例增加带原有集群密钥校验的 `/internal/monitor/operations`，只返回当前活跃数量与分片序号；外部 Nginx 仍阻止 `/internal/`。
- 概览直接读取本实例，并发读取其他实例的小计数。没有调用完整实时监控快照，不遍历账号、日志或图片索引，也不使用被截断的活跃请求列表。
- 汇总使用独立互斥与 1 秒缓存，同一时间多个管理页面共用一次查询；请求生命周期锁不会覆盖网络等待。远端 HTTP 使用 1 秒 socket 超时（不是强制 DNS 总截止时间）。
- 返回 `scope`、`expected_instances`、`responding_instances`、`complete`；缺失密钥、节点不可达、旧实例没有接口或无效响应都会标明统计不完整，不冒充零并发。
- 页面完整时显示“集群采样 · 8/8 实例”；部分响应时显示“≥ 已知数量”与警告。旧服务仍能打开概览，但明确标注“仅当前实例（旧版统计）”。原统计降级警告不会被覆盖。

统计口径保持原样：被实时监控追踪的在途生图请求，含排队、取号、生成、下载和后处理；不是账号数、配置的并发上限或单独的上游生成数量。普通文本请求原本不进入此计数，本次也没有扩大统计口径。各实例采样并非原子时刻；概览仍按用户原刷新间隔（默认 10 秒）更新，加上最多 1 秒缓存，不代表逐毫秒同步。

部署假设保持当前 Compose 的单 Uvicorn 进程/实例、唯一 `appN` 分片。不适用于在同一 app 容器内自行启动多个互不共享内存的 worker；未改变 worker 或并发配置。

## 导入任务与日志

- 服务端原来默认只返回最近 30 个任务。现在前端历史加载与连续提交也统一保留最近 30 个，修复弹窗一直开着、不断提交导致任务数组无限增长的问题。
- 保留每个任务最近 5000 个日志**事件**的现有内存上限，一个事件可能包含多条账号明细；这不是最多显示 5000 个账号。
- 明细仍每页最多渲染 100 条，原始日志与明细内部滚动，窗口固定高度，保持最小化功能。窄屏/矮屏使用下拉框提示和可访问描述，避免说明文字挤占明细空间。
- 这些都是显示上限，不删除数据库任务与事件。更早的任务/事件并不在当前弹窗完整展示；后台历史保留策略没有改变。

**没有修改导号底层**：AT/RT/JSON 解析、分批入库、兑换与额度同步、断点重试、后台调度均未改。没有修改生图处理、账号池选择、超分、限流参数、数据库结构、Compose、Nginx 或实际 `.env`。其他前端模块只同步缓存标记，避免混用两套 Vue 运行时。
