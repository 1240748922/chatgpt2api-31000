## 变更

1. 新的延后免费生成措辞要求同时含图像、升级订阅、用量重置信号。
   会话里的该匹配只用于 assistant/tool 的 text/system_error，不用于
   用户输入或 code。识别后使用现有 `image_quota_exhausted` 策略：
   标记账号额度问题并轮换，不消耗普通错误重试次数，仍遵守请求截止时间、
   已尝试账号去重和重试开关。无需等到 poll timeout。
2. 对“已完成空文本 + 已完成 recap”增加保守恢复：当前轮次不能含工具调用、
   code、非空正文、图片或异步任务标记；任务接口必须连续查询成功且为空；
   至少三次观察且内容稳定 15 秒，才返回 `no_image_generated` 进入普通换号
   重试。任何状态变化、任务出现或查询失败都重置观察；已找到图片优先交付。
   这是停滞恢复策略，不是上游绝对不会再发布结果的证明。
3. 有额度且无需立即刷新 AT 的账号优先；最多向后看 64 个池位置，找不到则
   回退原来的可刷新账号。没有跳过凭据校验，不改变额度、账号类型、分片、
   上传冷却或账号并发筛选条件。若候选都要刷新，仍可能等待凭据维护。
4. 步骤明细展示快照检查、候选取号、凭据维护三个已有分项，明确包含在
   “等待账号”总耗时内，不重复相加。监控事件投影和响应模型同步支持这些字段。

## 不变的行为与限制

* 明确的输入问题、审核和非空文字回复仍按原有策略处理，不改提示词，
  不用无限换号掩盖请求缺少参考图的可能性。
* 原有导号加速、数据库、配置文件、轮询上限、正常活跃任务、上传、超分、
  存储均不改。本版本未接入上一轮讨论的上传与页面预热并行方案。
* 不预热全量账号，不新增后台任务或网络探测。
* 测试使用合成会话、合成账号、临时 SQLite 与本地图片；没有消耗真实账号
  额度。上线后仍需用新请求验证真实上游状态与延迟。

## 部署验收

核对镜像 revision 与 `/version`（应用版本 `3.2.24`），不能仅以 `git pull`
成功判断容器已更新；`.env` 的 `CHATGPT2API_IMAGE_TAG` 若固定旧 sha，需要
改为本次构建发布的 sha 标签。重建服务会影响在途请求，应在低峰执行。
新日志中的额度措辞应为 `image_quota_exhausted` 而非 `image_poll_timeout`；
符合严格空结果条件的请求应记录 `poll_trace[].empty_terminal_ms` 与
`no_image_generated`，并受原有普通账号重试上限约束。
