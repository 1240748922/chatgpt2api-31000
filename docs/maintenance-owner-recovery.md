# 3.2.39：真实维护进度、恢复分类与网关验收

## 已确认的问题

现网截图显示“非维护实例、来源 app7”。只读对照确认后台维护实际在 app0
持续执行，网关管理接口却转到了 app7。宿主机 `nginx.conf` 已是动态路由，
但旧 gateway 的单文件挂载仍引用旧 inode；`nginx -t` 和 reload 成功并不代表
安装了新文件。另有大量历史 `refresh_token_reused`，不能把有 RT 一概当成
已经验证有效，也不能只根据旧错误文本自动删号。

## 本次改动

1. `/api/accounts/maintenance-status` 与 `/api/accounts/availability` 统一读取
   维护实例 app0 的状态。其他应用实例仅在必要时向固定 app0 内部端点读取
   只读内存数据；超时 2 秒，成功缓存 2 秒、失败缓存 1 秒，同实例合并请求。
   不转发管理员密钥、不经过环境代理、不跟随重定向、不增加全池扫描。
   内部接口仍受集群密钥保护，公网 Nginx 屏蔽 `/internal/`。
2. app0 暂不可达时显示明确提示和未知数值，不显示“正在处理 0 个”或假装
   没有执行。此降级保护不能替代网关修复，其他管理/导入/任务路由仍须正确。
3. 历史 OAuth 400/401 的明确终止错误、但尚无当前 RT 失效标记的账号，单列
   “历史失败待复核”，不再包含在常规“可尝试恢复”数里。这不是永久失效判断。
   已确认终止的 RT 保持不自动重试；历史待复核仍通过原有凭据租约/代际保护
   复核。每轮发现的常规续期候选优先于更早过期的历史失败候选。
4. 严格准入模式下，后台未知额度队列只同步凭据已就绪的账号。未就绪 AT
   交由续期队列，避免额度队列再次尝试相同失效凭据。手动同步、导入路径不变。
5. 对现网观察到的五种完整上游内容拒绝模板，日志分类由泛化文本回复改为
   `content_policy_violation`。保留上游原文和 HTTP 400，不惩罚账号、不换号
   重试，也不把拒绝伪装成成功。普通文本、引用、用户消息、未完成消息和已有
   图片输出不因这些模板误判。其他模型用量限制不据此当成图片额度耗尽。

不修改数据库结构、`.env`、生图/超分并发、维护批并发与性能阈值、导号加速、
自动删除开关、凭据租约或重试预算。有效 AT 即使 RT 有历史失败仍可正常派发。
本次由用户自行更新服务器，开发侧不重启服务、不批量改账号。

## 正确安装网关配置

更新镜像/应用的排空流程见 `VERSIONING.md`。用户服务器上已确认旧挂载问题，
本次更新务必包含 gateway 的重建，而不是只重载。若应用已经更新且仅需修复网关，
在暂停新流量、等待在途任务结束后执行：

```sh
docker compose --env-file .env config -q &&
docker compose --env-file .env stop -t 600 gateway &&
docker compose --env-file .env up -d --no-deps --force-recreate gateway &&
sh scripts/verify_gateway.sh
```

有短暂网关切换窗口；不重建 PostgreSQL 或其他应用，不删除卷。
不要把上述停机操作用于仍有在途生图的高峰。

`sh scripts/verify_gateway.sh` 本身只读：
- 比较宿主机/容器配置 SHA256，发现旧 inode 挂载即失败退出；
- 检查动态路由标记和 Nginx 语法；
- 从 app0 内部使用已有认证，核对经过 gateway 的概览实际仍是 app0，并验证
  维护进度的 `instance=app0, owner=true, available=true`；不输出认证值。
- 一次 HTTP 200、健康 `/version` 或容器 Up 均不足以代替这些检查。

## 验证与边界

本地合成测试覆盖管理认证、内部密钥、单实例无网络调用、app7→app0 转发、
缓存/并发合并、失败恢复、错误角色不被接受、RT 历史错误与确认失效区别、
有效 AT 保留、后台额度队列分工、网页导航/导入/关闭和小屏布局。

CI 真实 Docker/Nginx 回归增加“宿主机原子换文件 → 容器仍读旧文件 → reload
无效 → 仅重建网关后新文件生效”的对照，保留 DNS/IP 复用和在途 SSE 回归。

待补凭据增加常意味着后台确认了更多无法自动恢复的凭据，并非没有执行。
已被上游拒绝的旧 RT 仍需要最新有效凭据或重新登录，本版不能让它复活。
常规候选优先仅作用于每轮发现排序；未新增无限扫描、无界并发或在线重试。

回退应用可用 3.2.38 镜像，无需数据回滚；网关动态配置应保留。退回旧应用后
不具备跨实例进度兜底和历史失败单列，仍需确保网关正确指向 app0。
