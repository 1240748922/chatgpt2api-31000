# 3.2.33：就绪账号额度

概览中心和账号管理的“账号可用性”面板中，文生图、图生图候选数下方增加“就绪额度”。保留四张摘要卡，未知/无限额明细放在原有详情窗；窄屏卡片自动换行。

## 统计口径

- 复用可用性统计现有候选集合：AT 有效期明确且足以覆盖当前默认请求预算、状态正常、未鉴权隔离；严格模式还排除跨实例正在续期或续期结果不明的账号。
- **只合计这些账号的已知、正数剩余额度**。过期、有效期未知/不足、异常、禁用、待核验、限流账号的历史额度不会算入。
- `image_quota_unknown=true` 即便残留正数也不算已知额度；本地降到 0 但未远端确认耗尽的账号仍按原逻辑处理，不因新统计而被禁用。
- 无限额套餐沿用原 Pro/ProLite 识别，单独计账号数，不虚构数字额度。主卡数字后的 `*` 表示另有未知额度或无限额账号，悬停或点“详情”查看数量。
- 图生图另排除上传冷却账号；这些账号仍可能贡献文生图额度。**文生图/图生图额度重叠，不能相加。**
- 这是最近账号快照的统计，不是上游实时余额、实时空闲槽位或保证成功次数。最终派发仍检查模型、分片、来源、实际请求有效期预算和共享租约。兼容模式显示凭据就绪预评估，不改变原模式调度。

## 性能与兼容

- 只读计算在原 5 秒缓存内、账号调度锁外完成；前端沿用 15 秒刷新，不为统计发起额外上游核验或新增全池数据库读取。
- `/api/accounts/availability` 仅增量新增 `generation_quota`、`edit_quota`（各含 `known_remaining`、`known_accounts`、`unknown_accounts`、`unlimited_accounts`）及 `quota_note`，保持管理员权限；不返回 AT/RT。
- 老实例缺少字段时前端显示 `--`，不伪装成 0；接口暂时失败保留上次采样并显示提示。
- 未修改账号派发、额度扣减、AT/RT 导入、后台同步、预热、生图/超分并发或代理配置；无新增数据库表或配置项。

## 验证

合成账号回归覆盖各类不可用状态、跨实例刷新隔离、上传冷却、未知/无限额分离、缓存副本与权限。实际静态模块的 Chromium 测试验证两处面板、旧接口兼容、零值、长数字、详情关闭及原导入导航；不使用用户真实账号，也不消耗生图额度。
