# 3.2.36：正确终止已复用 RT 的续期

## 运行证据与原因

2026-09-24 提供的最近 5 条续期错误均为：

```text
oauth_refresh_http_401: refresh_token_reused:
Your refresh token has already been used to generate a new access token.
Please try signing in again.
```

这是上游拒绝当前保存的 RT，不是额度不足、账号数量过多，也不是 Nginx 502。
RT 轮换后旧值可以在原有效期结束前失效。AT 过期且 RT 不能兑换时，账号上仍显示
历史额度不代表可以执行生图。5 条样本不能证明全部待恢复账号都存在相同问题，
也不能确定 RT 被哪个进程使用、是否来自旧导出、外部刷新或历史轮换落库问题。

旧代码终止性 OAuth 错误列表漏掉 `refresh_token_reused`：记录了错误和临时退避，
却没写 `refresh_token_invalid_at`，退避结束后仍会选入续期候选。

## 本次变更

- 识别结构化 OAuth `refresh_token_reused`，走已有的凭据代际校验及 RT 失效落库。
  后台候选扫描与批量刷新不再反复兑换已确认失效的 RT。
- 保留有效 AT、额度与账号，不因 RT 失效自动删除账号或清零额度。
  AT 仍满足准入条件时继续派发；AT 过期且 RT 确认失效时计入“需补凭据”，
  不再计入“可尝试恢复”。
- 更新/覆盖导入不同 RT 时清除旧 RT 的错误和退避时间，避免新凭据被旧失败暂缓。
  重复同一 RT 不清失效标记；备份恢复保留生命周期；原快速导入的跳过重复策略不变。
- 408、429、5xx、未知错误和网络超时不因此永久判废 RT。
  保留共享刷新互斥、结果不确定时不重放、远端轮换/删除胜出的原保护。

不修改生图/超分并发、维护压力阈值、预热、代理、前端或真实部署配置，无数据库迁移。
不清理共享凭据租约和发送记录，不在启动时全池改写。

## 历史数据与恢复边界

历史错误没有对应 RT 代际指纹，不能仅靠旧文本批量把当前 RT 标为无效：
某些覆盖导入路径此前可能保留旧错误，但当前 RT 已是新值。
本次只在下一次允许的续期得到明确拒绝后，按同代条件标记。
已有共享 `sent` / `uncertain` 保护仍生效，不会为了补标记强制重放兑换。

确认复用的旧 RT 不能靠增加重试次数恢复。应从凭据来源取得最新一对 AT/RT，
或重新登录取得新凭据；不能只重复导入旧文件。不要批量删除 AT 仍有效的账号。
本补丁不承诺所有分片立刻都有就绪账号，也不解决所有其他续期错误。
